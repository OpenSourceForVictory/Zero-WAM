# Action chunk延迟统计（2026-10-13）

参考论文Real-Time Execution of Action Chunking Flow Policies第2节：
https://arxiv.org/pdf/2506.07339 。δ为观测到动作块可用的延迟，
d=floor(δ/Δt)，H为预测动作数，s为执行动作数。RTC连续覆盖条件含d≤H−s。

本次通过175→工作站→模型服务器现有隧道实测3个连续chunk，不加载机器人SDK、
不发送运动、不修改硬件软件停止标志。采用已保存的固定RGB观测和关节状态，
KV更新重复同一观测构造4/8帧历史，用于延迟测试，不代表真实闭环轨迹。
第1块为reset后首块（模型已在内存，不是模型冷启动），其后两块有KV历史。
同时发生一次独立机械臂恢复回零操作，未由benchmark触发，不占用模型服务。

服务：昇腾910B3设备7，lingbot-vggt，aloha_step6000_validation/model；
steps=50，chunk-frames=2，breakfast/bread_test000，预测记录开启。
视频分支51次Transformer前向、动作分支50次前向；不等于只有50次总前向。

## 论文符号逐项对应（补充）

- Δt：控制采样周期。本客户端名义0.02s（50Hz）；存在关键帧等待，实际执行不是严格50Hz。
- δ：观测可用到完整动作块可用的时间。本次客户端计时包含传输/记录，不含后续KV更新。
- d=floor(δ/Δt)：推理期间经过的控制周期数，不是降噪步数。
- H：预测的未来动作长度。输出张量有32个时间位置，但第1块前16个属于初始latent，
  被客户端跳过，因此首块有效未来动作长度按16计；后续块为32。
- s：选取该块中多少步执行后再次规划。现有同步客户端执行全部剩余动作，
  按平滑前动作索引，首块配置s=16，后续s=32；并未采用RTC的提前重规划。
- 本benchmark不执行机械臂，所以实测s_executed=0。下表s是现有控制流程的配置映射，
  不是这次计时实验测得的运动步数。spline插值后的下发条数可能增加，应另计N_sent。

对后续块使用H=32、s=32时，H−s=0；论文异步覆盖条件d≤H−s不成立。
即便改为s=16，剩余覆盖也只有16步/0.32秒，远小于实测37–39秒。
这些是用名义周期进行的可行性估算，不能当作本系统已实现RTC的运行指标。
若按训练准备的30Hz时间基准，三块d分别为1155、1135、1121，结论仍不改变；
正式RTC实现前需要统一训练时间基准、下发周期与实测动作执行周期。

当前同步路径还包括独立KV更新：第1块8.545612s、第2块14.233770s。
动作执行结束后，若KV更新完全串行阻塞，直到下一块可用的等待分别为：
KV1+δ2=46.383788s；KV2+δ3=51.606752s（不含额外取图/格式化）。
该“块间等待”与δ不同，不能混成一个降噪耗时。
